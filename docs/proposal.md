# Предварительная защита

## Что подготовить

- В таблице выступлений: номер команды **4**, доступная ссылка на презентацию и [GitHub](https://github.com/filipp05/Multi-agent-builder).
- Состав и номер команды должны совпадать с таблицей участников.
- По сообщению преподавателя: ссылки — до 23:59 Москвы накануне выступления; подключиться за 5 минут с камерами.
- Каждый из четырёх участников рассказывает хотя бы один слайд. Время доклада — 10 минут, затем вопросы.
- Проверить права на презентацию без авторизации. Локальный путь к PPTX и localhost не заменяют ссылку на презентацию в таблице.

Публичную ссылку на конкретную презентацию добавит команда после загрузки. Не публикуйте личные notes и доступ к серверу автоматически.

## Демо и честные формулировки

Рабочий путь — [локальный Codex](local-development.md). При блокировке AWS не менять провайдера перед выступлением без успешного реального прогона. Интернет для Codex нужен.

Показать новый запрос и уточнение; затем подтверждение и две концепции. Для соблюдения времени заранее открыть сохранённый полный расчёт: закупки, смета, график, замечания аудитора. Назвать его сохранённым реальным результатом. Короткая запись или скриншоты — резерв на случай технического сбоя.

Называть систему фиксированным многоэтапным LLM-workflow. Автоматического адресного исправления после аудита нет. Восемь документов уже получены живым проходом; следующий этап — повторные сценарии и оценка качества. 88/90 относятся только к первому этапу, не ко всей системе. Каталог и нормы учебные, изображения/3D ещё не реализованы.

[Официальные требования](https://github.com/AlgazinovAleksandr/LLM-Agents-Course/blob/main/GROUP_PROJECT.md). Серверный деплой отдельно оценивается на финальной защите; proposal можно показывать локально.
