# План стыковки: уточнения существующих задач

После указания продолжать оформлены [четыре задания](issues) для начала работы. Они уточняют задачи 01–08, не добавляя объём или баллы. Публикация локальная, GitHub Issues не создавались.

1. **Миша: требования → выбранная концепция → состав работ** (02/05).
   **Блокируется:** ничем; входы доступны в общем примере.
   **Результат:** пользователь видит две концепции, выбирает одну и получает работы с потребностями. Выход соответствует договору; неподдерживаемое требование показано явно. Проверка: выбор влияет на результат, несовместимое решение не принимается.

2. **Олег: работы → корзина → проверяемая смета** (03/06).
   **Блокируется:** ничем для реализации на общем примере; реальные данные Миши нужны для окончательной интеграции.
   **Результат:** пользователь видит упаковки, источники, работу, доставку, резерв и итог относительно бюджета. Проверка: контрольная сумма 74 250 ₽, округление упаковок, неизвестная доставка не становится нулём.

3. **Карина: комплект → график → замечания** (04/07).
   **Блокируется:** ничем для реализации на общем примере; реальные данные Миши и Олега нужны для окончательной интеграции.
   **Результат:** пользователь видит календарь и объяснение найденной ошибки. Проверка: поздняя поставка и технологическая пауза сдвигают сроки; намеренный пропуск или дубль обнаруживается независимым расчётом.

4. **Филипп: запрос → общий результат → пересмотр бюджета** (01/08).
   **Блокируется:** 1–3 для завершения общей сборки; ввод требований, хранение, выбор концепции и диспетчеризацию можно делать сразу.
   **Результат:** пользователь проходит весь путь с настоящим вызовом модели и получает комплект одной ревизии. Проверка: изменение бюджета создаёт новую ревизию, устаревший ответ отвергается, нарушенные ограничения не объявляются успехом; соблюдаются пределы повторов.

Граница приёмки общая: целый комплект плюс ответы этапов. Владельцы исправляют свои результаты; Филипп отвечает за связывание и принятие результатов. Каждый делает показ своей части, а не только внутреннюю функцию.

Начинать можно независимо на общем примере. Для Филиппа зависимости блокируют только завершение интеграции. Если в реализации обнаружится несовместимость, обновляем общий договор вместе с примерами и проверками.
