# 10: Источники рекомендаций и поиск по техническим карточкам

**Что сделать:** Пользователь раскрывает рекомендацию и видит релевантную техническую карточку или явно обозначенное отсутствие доказательства.

**Зависит от задач:** 05: Технологические ограничения и совместимость материалов.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Миша (B). **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Подготовлены минимум 12 технических карточек: область применения, основание, расход или пауза, источник, версия. Вымышленные данные помечены.
- [ ] Поиск по метаданным и ключевым словам возвращает ограниченные выдержки, которые получает модель. Просто добавленная ссылка не считается поиском по источникам.
- [ ] Интерфейс показывает источник, тип и дату данных. Отсутствие подтверждения остаётся неизвестным, а не заменяется выдуманной ссылкой.
- [ ] На 10 запросах с заранее известными подходящими карточками измеряется полнота поиска среди первых трёх результатов (`recall@3`). Приёмка отклоняет несуществующий источник.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
