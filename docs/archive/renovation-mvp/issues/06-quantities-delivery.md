# 06: Точные упаковки, доставка и полный бюджет

**Что сделать:** Пользователь получает закупаемое количество с запасом и округлением, стоимость доставки корзины и честное сравнение общего итога с бюджетом.

**Зависит от задач:** 03: Каталожная корзина и прозрачная смета.

**Статус:** ready-for-agent. Общие контракты и критерии стыковки подготовлены в репозитории.

**Ответственный:** Олег (C). **Сложность:** 5 баллов. **Этап:** MVP для предварительной защиты.

## Критерии приёмки

- [ ] Площадь стен учитывает проёмы, краска — слои, покрытие пола — запас. Проверяются единицы измерения.
- [ ] Пример комнаты 4×5×2.7 м с проёмами 4 м² даёт 44.6 м² стен, 9.812 л краски и две банки по 5 л; для пола — десять упаковок по 2.2 м².
- [ ] Доставка учитывается один раз на заказ у поставщика. Неизвестная доставка запрещает считать смету полной.
- [ ] Интерфейс раскрывает сумму до резерва, базу и ставку резерва, общий итог и нехватку бюджета. В контрольном примере итог — 74250 ₽.
- [ ] Приёмочный тест API обнаруживает округление упаковок вниз, повтор доставки и уменьшение резерва без изменения правил.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
