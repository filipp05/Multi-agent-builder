# 18: Осознанный выбор дизайна с техническими последствиями

**Что сделать:** Пользователь сравнивает два направления по пожеланиям, материалам и необходимой подготовке, затем фиксирует выбор в плане.

**Зависит от задач:** 09: Уточнение и подтверждение брифа; 10: Источники рекомендаций и поиск по техническим карточкам; 14: Неизвестное основание и подготовительные работы.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Миша (B). **Сложность:** 5 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Сравнение содержит палитры, категории материалов, соответствие пожеланиям и источники. Иллюстративные изображения помечены.
- [ ] Выбор передаёт идентификатор концепции и версию, меняет план работ; зависимые результаты устаревают до пересчёта.
- [ ] Неизвестное основание видно в обеих концепциях. Новый стиль не снимает обязательные ограничения.
- [ ] Приёмочный тест API и проверка в браузере исключают смешение версий при выборе. Люди оценивают различимость вариантов по единым критериям.
- [ ] Генерация изображений и 3D не входят в задачу. Решение полезно без внешнего API изображений.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
