# Закрытый серверный MVP

Один Linux VPS, Docker, Caddy с HTTPS и общей Basic Auth для команды. GPU не нужен: модель вызывается через API. 3 CPU / 8 ГБ достаточно для текущего небольшого веб-приложения. Это не запуск большой LLM на VPS.

Полная команда запуска контейнера с постоянным volume находится в [README](../README.md#запуск-docker-с-aws-bedrock).

## Сборка и тесты

Из корня репозитория:

```bash
docker build --target test -t renovation-mvp-test .
docker run --rm renovation-mvp-test
docker build --target runtime -t renovation-mvp .
```

Тестовая сборка содержит Chromium и все автоматические проверки. Runtime их не содержит, работает от UID 10001.

## Конфигурация

Файл вне репозитория с правами 600, например `/opt/renovation-mvp/bedrock.env`:

```dotenv
AWS_BEARER_TOKEN_BEDROCK=<установить приватно>
AWS_REGION=us-east-2
```

Не присылайте значение в чат/PR. Short-term key действует не более 12 часов и может истечь раньше вместе с сессией. После обновления файла контейнер нужно пересоздать: `docker restart` не перечитывает env-file. Для длительной работы отдельно выберите постоянный механизм доступа с ограниченными правами.

Настройки приложения:

| Переменная | По умолчанию / смысл |
|---|---|
| `MODEL_PROVIDER` | `bedrock`; также есть локальный `codex`, требующий установленного CLI и личной авторизации |
| `AWS_REGION` | `us-east-2`; другие регионы в этой версии отклоняются |
| `BEDROCK_MODEL_ID` | `amazon.nova-lite-v1:0` |
| `MODEL_BUDGET_USD` | `5`, общий сохраняемый счётчик оценки расходов |
| `MODEL_INPUT_USD_PER_MILLION`, `MODEL_OUTPUT_USD_PER_MILLION` | Явные ставки обязательны для модели вне встроенного списка |
| `RENOVATION_DATA_DIR` | `/data` внутри Docker |
| `ALLOWED_HOSTS` | Список имён хоста через запятую, без схемы и портов |

Базовые оценки Nova Lite: $0.06/$0.24 за миллион входных/выходных токенов. Проверяйте действующий тариф до изменения конфигурации. Баланс кредитов AWS и токенные квоты — разные ограничения.

## Существующий Caddy

Поместите новый контейнер в ту же Docker-сеть, что и Caddy. Сохраните действующие домен, сертификаты и Basic Auth. Создайте отдельный каталог данных с владельцем 10001. Не публикуйте порт приложения на `0.0.0.0`: внешний вход только через Caddy. Укажите точный IP Caddy в `--forwarded-allow-ips`; иначе HTTPS Origin может быть отклонён приложением.

После проверки `/health` внутри сети поменяйте upstream Caddy на `renovation-mvp:8000`, проверьте конфигурацию и выполните reload. `/health` проверяет процесс, а не способность модели отвечать. Перед сменой сохраните Caddyfile; откат — вернуть старый upstream и reload. Старые данные не удалять.

## Проверка после запуска

- Внешний HTTPS без авторизации возвращает 401; с авторизацией доступны `/` и `/plan`.
- Создать бриф → подтвердить → получить концепции → выбрать → дождаться восьми документов.
- Если квота AWS нулевая или ключ истёк, интерфейс должен показать ошибку. Это не успешный end-to-end запуск.
- Перезапуск сохраняет проекты, ревизии и счётчик расходов.
- Копировать SQLite для резервной копии при остановленном приложении либо штатным SQLite backup API.

При нулевой квоте: Service Quotas → Amazon Bedrock в Ohio, проверить Applied account-level quota. Если Not adjustable, обратиться в AWS Support с регионом, моделью, ошибкой и скрином. Повтор HTTP-запросов и VPN не увеличивают квоту. Не менять платёжный план в расчёте на гарантированное исправление.

Документация: [квоты Bedrock](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas.html), [запрос увеличения](https://docs.aws.amazon.com/bedrock/latest/userguide/quotas-increase.html).
