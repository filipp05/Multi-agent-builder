# Закупки и смета: этап C (Олег)

> Модульная инструкция. Общий актуальный запуск и статус — в [README проекта](../../README.md) и [локальной инструкции](../local-development.md). Исторические числа тестов и результаты ниже относятся к указанным этапам, а не ко всему текущему приложению.


План работ → корзина упаковок → смета с доставкой и резервом → сравнение с бюджетом. Задачи [03](../archive/renovation-mvp/issues/03-basket-estimate.md), [06](../archive/renovation-mvp/issues/06-quantities-delivery.md), критерии стыковки [02-oleg](../archive/shared-contracts/issues/02-oleg.md).

Модель выбирает предложения (снабженец) и объясняет строки (сметчик). Количество упаковок, цены, доставку, резерв и итог считает код через `Decimal` и целые копейки. Бриф, концепции и план работ на время разработки берутся из [учебного примера](../../contracts/examples/completed.json) и на странице помечены как готовые данные, не результат модели.

## Запуск

Из корня репозитория, после установки `requirements-dev.txt` (см. [FILIPP_MVP.md](brief.md)):

    python -m app.procurement.cli                 # контрольный пример без модели: 74 250 ₽ и проверка общего комплекта
    python -m app.procurement.cli --model         # настоящий выбор и пояснения через Codex; журнал в .scratch/oleg-mvp/results/
    python -m uvicorn app.procurement.api:app --host 127.0.0.1 --port 8001

Страница: http://127.0.0.1:8001/oleg/. Кнопка «Рассчитать по этому выбору» считает без модели по выбору `{requirement_id: offer_id}`; «Подобрать и объяснить моделью» вызывает Codex. На Windows нужен пакет `tzdata` (общий валидатор использует `Europe/Moscow`).

## Устройство

- `app/procurement/data/catalog.json` — версионированный учебный снимок: 14 предложений от трёх поставщиков, все `synthetic` с датой. Включает совместимые аналоги и ловушки: дешёвый ламинат для влажных помещений, фасадная краска, краска в кг, поставщик с неизвестной доставкой.
- `app/procurement/data/rates.json` — доставка по поставщикам (store-1 2 500 ₽, store-2 подтверждённый 0, store-3 неизвестно), фиксированные тарифы работ с пределом объёма, правило резерва `reserve-v1` 10%.
- `calc.py` — площадь стен, краска, упаковки ⌈потребность × (1 + запас/100) / упаковка⌉, одна доставка на поставщика, резерв `ROUND_HALF_UP`.
- `stages.py` — обработчики `procurement_handler(choices)` и `estimate_handler()` по интерфейсу `handler(context) -> (result, artifact)`. Неверный вход — `failed` / `INVALID_INPUT` с `field_paths`, без документа.
- `agents.py` — снабженец видит только совместимых кандидатов с уже посчитанными суммами, его ответ проверяется по списку кандидатов. Сметчик обязан пояснить каждую строку ровно один раз. Модель — `CodexModel` Филиппа.
- `check.py` — независимый пересчёт присланных документов: округление вниз, повтор доставки, изменённая ставка резерва, двойной учёт, неверные суммы.
- `service.py`, `api.py`, `static/` — сервис, API (`/oleg/api/example`, `/oleg/api/run`, `/oleg/api/check`) и отдельная страница. `router` можно подключить к общему приложению.

## Пример

Вход: учебный план работ (грунт 1 set, краска 8.92 л + 10%, ламинат 20 м² + 10%) и выбор `primer, paint, floor`. Выход:

| | Расчёт | Сумма |
|---|---|---|
| Грунт | 1 set → 1 уп. × 4 000 ₽ | 4 000 ₽ |
| Краска | 9.812 л → 2 банки по 5 л × 3 000 ₽ | 6 000 ₽ |
| Ламинат | 22 м² → 10 уп. по 2.2 м² × 2 000 ₽ | 20 000 ₽ |
| Работа | подготовка, покраска, укладка | 35 000 ₽ |
| Доставка | store-1, один раз | 2 500 ₽ |
| База | | 67 500 ₽ |
| Резерв 10% | reserve-v1 | 6 750 ₽ |
| **Итог** | бюджет 80 000 ₽ — укладывается | **74 250 ₽** |

Документы подставляются в общий пример и проходят `validate_bundle` и восемь передач `verify_handoffs`.

## Проверки

    python -m pytest -q tests/procurement

Покрыто: эталон 74 250 ₽, превышение бюджета, неизвестная доставка, бесплатная доставка, неизвестный артикул, несовпадающая валюта, несовместимый дешёвый товар, неверные единицы, отсутствие тарифа, подмены (округление вниз, повтор доставки, снижение резерва без смены правила), выбор модели вне кандидатов, неполные пояснения, недоступная модель. Модель в pytest — явная тестовая замена `FakeModel`.

## Ограничения

- Настоящий вызов модели не выполнялся: на машине разработки нет Codex CLI. Режим модели проверен только на тестовой замене. Журнал реального вызова нужно получить командой `--model` там, где Codex установлен.
- Все цены и тарифы учебные (`synthetic`); наблюдаемых источников нет.
- Тарифы работ фиксированные на комнату с пределом объёма; по количеству × ставке — расширение договора.
- Одна потребность — одно предложение; смесь упаковок не поддерживается.
- Площадь стен считается для сверки; чистую потребность в краске передаёт план работ (Миша).

## Вопросы к договору 0.1.0

1. Тарифы доставки и работ не входят в контекст этапа (только `sources` и `offers`). Сейчас сервис добавляет источник `oleg-rates-2026-10-21` к снимку источников сам — нужно согласовать с Филиппом.
2. В смете нет поля для пояснений сметчика (`additionalProperties: false`). Пояснения возвращаются рядом с документом, а не в нём.
3. Общий валидатор не сверяет ставку резерва с правилом: согласованно сниженный резерв проходит `validate_bundle`. Это ловит `check.py`; стоит обсудить с Кариной для аудита.
4. Валюту предложения сейчас проверяет схема (`RUB`) и обработчик; в `validate.py` проверки нет.
