# Локальный прораб: первый этап

Пожелания → настоящий Codex exec → уточнения → сводка → подтверждение пользователем. Данные и история сохраняются в SQLite; отмена, повтор, редактирование и перезапуск сохраняют ввод. Старые подтверждённые документы сохраняются отдельно от нового черновика.

Поддерживается покраска стен и ламинат в одной прямоугольной сухой комнате. Электрика явно исключается с предупреждением; остальные несогласованные виды работ блокируют подтверждение. Полный ремонт, дизайн, закупки, смета и расписание ещё не реализованы как настоящие агенты.

## Установка и запуск

Нужны Python3.12 и Codex CLI с входом через ChatGPT. Проверенная при разработке версия CLI —0.155.1. Локальным является процесс CLI; инференс выполняет удалённый сервис Codex. Лимиты подписки сохраняются; платного API fallback нет.

Из корня репозитория:

    python3.12 -m venv .venv
    .venv/bin/python -m pip install -r requirements-dev.txt
    codex login status
    # Если входа нет: codex login
    .venv/bin/python scripts/filipp_codex_smoke.py
    .venv/bin/python -m uvicorn app.filipp.api:app --host 127.0.0.1 --port 8000

Откройте http://127.0.0.1:8000. Пример: «Покрасить стены и уложить ламинат в комнате5×4м, высота2,7м, проёмы3м². Бюджет200000руб., Москва. С1ноября2026 до1декабря2026 включительно». Для других дат укажите актуальные значения.

Для запуска без инструментов разработки достаточно requirements-app.txt. Установка Codex и вход в аккаунт выполняются отдельно. Smoke действительно вызывает модель по подписке; обычный pytest моделей не вызывает.

## Устройство

- app/filipp/model.py: изолированный subprocess, проверка входа ChatGPT, JSON Schema, таймаут, отмена и диагностика. Уведомления о переподключении допустимы только после успешного завершения того же вызова.
- service.py и brief.py: источники фактов, уточнения, конфликты формы/текста, ограничения и подтверждение. Схема ограничивает input_id реальными сообщениями; цитаты проверяются отдельно. Несколько пожеланий из изменения объединяются; очистка списков задаётся полями формы, противоречащий текст требует уточнения.
- repository.py: SQLite, версии, идемпотентные команды, сохранение истории.
- api.py, presentation.py, static/, templates/: локальный интерфейс; устаревшие ответы не переключают выбранный проект.
- stages.py: передача подтверждённого brief через общие контракты.

## Проверки

    PLAYWRIGHT_BROWSERS_PATH="$PWD/.scratch/filipp-mvp/runtime/browsers" .venv/bin/python -m playwright install chromium
    .venv/bin/python -m pytest -q

В GitHub Actions контрактные и прикладные проверки разделены; app-job устанавливает Chromium. Настоящий Codex и платная оценка в CI не запускаются. На Linux при ручной установке браузера могут понадобиться системные зависимости: playwright install --with-deps chromium.

Настоящее измерение запускается отдельно; два независимых процесса можно выполнить одновременно:

    .venv/bin/python -m evals.filipp.run --split dev --repeats 3 --concurrency 3 --name dev-review-001
    .venv/bin/python -m evals.filipp.run --split holdout --repeats 3 --concurrency 3 --name holdout-review-001

20dev+10holdout, каждый сценарий×3. Holdout уже известен: это регрессия, не слепая проверка. Новый код требует нового имени запуска; сохранённые провалы не заменяются удачными повторами. Exit0 означает завершение измерения: приёмку смотрите в summary.json → gate.complete_acceptance.

Пороги в evals/filipp/manifest.json: critical0, точность/полнота≥98%, уточнения100%, поддерживаемый успех≥95%, устойчивые сценарии≥90%, корректные отказы100%, p95≤45с. Для сценария с редактированием expected_initial применяется до отправки edit, expected_final — после; недостигнутый шаг остаётся провалом, но не объявляется изменением ещё не введённого факта.

Проверка изоляции scripts/filipp_isolation_probe.py делает настоящий вызов с временным несекретным canary; exit1 означает провал. Это проверка конкретного запуска, не универсальное доказательство безопасности. После обновления CLI повторите smoke и canary.

## Необязательный оценщик

evals/filipp/judge.py требует отдельно установленного Eliza helper; он не входит в репозиторий. Укажите путь через ELIZA_HELPER или установите в ~/.codex/skills/eliza-external-models/scripts/eliza.py. Путь проверяется до запуска; секреты и конфигурацию доступа не добавляйте в Git.

Пул quality-ai, модель anthropic/claude-opus-5.5, лимит$20 настроены для текущего эксперимента. Новое применение требует разрешённого доступа и бюджета. Общий ledger используется всеми процессами и повторными запусками; удаление/смена ledger обнуляет локальный учёт и не допускается ради повторной траты лимита. Без --send выполняется подготовка/проверка helper; --send делает платные вызовы. Оценки модели не заменяют проверки фактов кодом.

## Локальные данные и ограничения

Вся .scratch/filipp-mvp/ исключена из Git: SQLite, ответы, результаты, чеки, журналы и рабочие заметки. .venv/, браузеры и секреты тоже не публикуются. Для воспроизведения достаточно кода, синтетических сценариев и зависимостей; результаты конкретного пользователя не нужны.

Приложение рассчитано на одного локального пользователя и один серверный процесс. Формат CLI и доступность модели могут меняться. Отказы внешнего сервиса остаются возможными; ввод сохраняется, при ошибках предлагается ручное действие. Предупреждение Starlette/HTTPX не мешает закреплённым версиям тестов.
