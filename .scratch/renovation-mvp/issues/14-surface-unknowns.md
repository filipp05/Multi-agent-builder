# 14: Неизвестное основание и подготовительные работы

**Что сделать:** Если состояние поверхности неизвестно, пользователь видит вопрос или явно условный сценарий подготовки вместо скрытого допущения.

**Зависит от задач:** 05: Технологические ограничения и совместимость материалов; 09: Уточнение и подтверждение брифа.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** B. **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Поддерживаются состояния «подготовлено», «нужна подготовка» и «неизвестно» с различающимися планами работ.
- [ ] При неизвестном основании нельзя выдать безусловно проверенный итог. Интерфейс показывает нужные сведения и влияние на объём работ.
- [ ] Подтверждение состояния меняет версию и зависимые расчёты через прораба.
- [ ] Приёмка проверяет переход от неизвестного состояния к подтверждённому и запрещает исключать обязательную подготовку ради экономии.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
