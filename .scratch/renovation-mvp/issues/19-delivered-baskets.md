# 19: Сравнение корзин по полной стоимости

**Что сделать:** Пользователь сравнивает минимум две корзины с разными поставщиками и видит, какая реально дешевле с учётом упаковок и доставки.

**Зависит от задач:** 11: Объяснимые совместимые аналоги; 15: Резерв, расходники и происхождение цены.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Олег (C). **Сложность:** 5 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Каталог расширен минимум до 24 предложений с идентификаторами поставщиков и описанными правилами доставки.
- [ ] Сравнение учитывает минимальный заказ, упаковки, отдельные доставки и сроки поставки, а не только цену единицы.
- [ ] Глобальная оптимальность не заявляется: перебирается ограниченный набор кандидатов. Алгоритм и границы поиска описаны.
- [ ] Интерфейс показывает составляющие цены и компромиссы; выбор передаётся прорабу как новая версия.
- [ ] Приёмка включает случай, когда минимальная цена товара приводит к более дорогой корзине.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
