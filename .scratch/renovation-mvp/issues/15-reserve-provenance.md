# 15: Резерв, расходники и происхождение цены

**Что сделать:** Пользователь понимает, какие расходы включены, какой резерв заложен и какие цены требуют перепроверки.

**Зависит от задач:** 06: Точные упаковки, доставка и полный бюджет.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Олег (C). **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Смета разделяет материалы, работу, доставку, прочие расходы и резерв. Исключённые категории видны.
- [ ] У каждой строки указаны тип источника, дата, регион и единица измерения. Устаревший снимок не выдаётся за проверку текущего наличия.
- [ ] Изменение правил резерва явно и версионируется. Запас материалов не смешивается с денежным резервом.
- [ ] Приёмка охватывает неизвестную доставку, устаревший источник и корректное изменение резерва. Интерфейс объясняет неполную итоговую сумму.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
