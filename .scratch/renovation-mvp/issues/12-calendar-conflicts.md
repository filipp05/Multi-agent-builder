# 12: Рабочий календарь и сроки закупок

**Что сделать:** Пользователь меняет дату старта/календарь и получает пересчитанный график с объяснением критичных поставок.

**Зависит от задач:** 04: График ремонта по зависимостям.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Карина (D). **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Рабочие часы отличаются от календарного времени сушки. Выходные учитываются по явно заданному календарю.
- [ ] Для каждой покупки указаны дата необходимости и крайняя дата заказа либо неизвестный срок поставки.
- [ ] Интерфейс объясняет, что задерживает ремонт и почему срок невыполним; не предполагает невозможную параллельную работу одной бригады.
- [ ] Приёмка охватывает пятничный старт, выходные, позднюю поставку и точную границу технологической паузы.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
