# 09: Уточнение и подтверждение брифа

**Что сделать:** Пользователь отвечает на существенные уточнения и подтверждает интерпретацию требований до расчёта.

**Зависит от задач:** 08: Полный путь с настоящей моделью и один пересмотр бюджета.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** A. **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Недостающие обязательные сведения приводят к состоянию `needs_input` и короткому списку вопросов. После двух автоматических раундов остаётся явная форма ввода.
- [ ] Подтверждённый бриф получает версию. Неизвестные сведения, допущения и подтверждённые факты представлены отдельно.
- [ ] Изменение бюджета или размеров помечает текущий запуск как устаревший, даже если модель завершит его позже.
- [ ] Тест API и интерфейса проверяет неоднозначный запрос, подтверждение и конфликт ожидаемой версии `expected_revision`.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
