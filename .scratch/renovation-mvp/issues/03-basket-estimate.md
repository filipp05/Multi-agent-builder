# 03: Каталожная корзина и прозрачная смета

**Что сделать:** По примерным потребностям пользователь видит выбранные товары, стоимость материалов и труда и сводный итог с отдельным резервом.

**Зависит от задач:** Нет — можно начинать после согласования первой версии контрактов данных.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** C. **Сложность:** 5 баллов. **Этап:** MVP для предварительной защиты.

## Критерии приёмки

- [ ] Подготовленный снимок каталога содержит минимум 12 предложений по нужным категориям, включая совместимые аналоги. Вымышленные и полученные из источников данные различаются; дата указана.
- [ ] Снабженец выбирает только существующие идентификаторы; сметчик объясняет статьи. Суммы считает код с Decimal или целыми копейками.
- [ ] Интерфейс показывает покупки и строки сметы со ссылками на требования и источники, а также валюту. Неизвестная цена не превращается в ноль.
- [ ] Приёмочный тест API получает заранее рассчитанные суммы и отклоняет неизвестный артикул и несовпадающую валюту.
- [ ] Отдельная страница принимает тестовый пример по первой версии контрактов. Настоящий вызов модели проверяет выбор и объяснение, а не арифметику.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
