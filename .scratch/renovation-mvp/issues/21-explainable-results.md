# 21: Понятный итог для владельца жилья

**Что сделать:** Пользователь получает читаемую итоговую страницу с четырьмя связанными результатами, допущениями и конкретным следующим действием.

**Зависит от задач:** 17: Две ограниченные итерации и сравнение версий; 18: Осознанный выбор дизайна с техническими последствиями.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** B. **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Экран различает завершённый расчёт, запрос сведений, ожидание подтверждения, нерешённые ограничения и техническую ошибку.
- [ ] Виден общий номер версии, исключённые работы, неизвестные данные и причины компромиссов. Внутренние трассировки ошибок и скрытые рассуждения не показываются.
- [ ] На узком экране таблицы и кнопки позволяют пройти основной сценарий.
- [ ] Проверка в браузере охватывает успех и нерешённый конфликт. Минимум два человека проверяют понятность и записывают замечания.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
