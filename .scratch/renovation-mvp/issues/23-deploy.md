# 23: Работающий сервис по ссылке

**Что сделать:** Другой человек открывает развёрнутый сервис, создаёт свой план и не получает доступ к чужому проекту.

**Зависит от задач:** 13: Сохранение и продолжение расчёта; 17: Две ограниченные итерации и сравнение версий; 21: Понятный итог для владельца жилья; 22: Согласованный экспорт плана и покупок.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** A. **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Образ Docker запускается на сервере с постоянным томом, безопасной передачей секретов и проверкой состояния сервиса. Инструкцию повторяет второй участник.
- [ ] До открытия внешнего доступа включены проверка принадлежности проекта пользователю, серверное хранение ключа и квоты запусков, запросов и расходов. Доступ к чужому проекту отклоняется.
- [ ] Перезапуск сохраняет данные. Описанный откат возвращает предыдущий образ без потери согласованных документов.
- [ ] README содержит настоящие ФИО и имена GitHub, поставщика API и модель, проверенные команды и ссылку на сервис. Открытый доступ к репозиторию либо доступ преподавателя проверен.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
