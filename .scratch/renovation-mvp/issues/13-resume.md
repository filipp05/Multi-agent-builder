# 13: Сохранение и продолжение расчёта

**Что сделать:** Пользователь возвращается после рестарта и продолжает свой расчёт с последнего принятого этапа.

**Зависит от задач:** 09: Уточнение и подтверждение брифа.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** Филипп (A). **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] Контрольные точки и неизменяемые документы хранятся на постоянном томе. Перезапуск не теряет подтверждённый бриф и решения.
- [ ] Ключ идемпотентности предотвращает дублирование запуска при повторном запросе.
- [ ] Действия до прерывания безопасно повторяются. Запоздалые и устаревшие результаты не становятся текущим планом.
- [ ] Интерфейс показывает сохранённое состояние и продолжение. Тест останавливает процесс после принятого документа и проверяет согласованное возобновление.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
