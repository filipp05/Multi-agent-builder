# 05: Технологические ограничения и совместимость материалов

**Что сделать:** Пользователь получает только варианты с явно проверенной совместимостью основания, покрытия и расходников; неподдерживаемые решения требуют уточнения.

**Зависит от задач:** 02: Две концепции и состав работ для одной комнаты.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** B. **Сложность:** 5 баллов. **Этап:** MVP для предварительной защиты.

## Критерии приёмки

- [ ] Справочник содержит минимальные шаблоны работ, предварительные условия и правила совместимости со ссылками на источники либо отметкой об учебном допущении.
- [ ] Выбор покрытия обновляет план работ и требования к материалам. Интерфейс объясняет отклонение несовместимой комбинации.
- [ ] Пропущенная подготовка, неизвестное основание и неподдерживаемая мокрая зона дают структурированные замечания, а не выдуманное решение.
- [ ] Приёмочные проверки охватывают две допустимые и две запрещённые комбинации, а также сохранение обязательных работ.
- [ ] Прораб может принять и передать результат дальше. LLM не отменяет обязательное правило текстовым объяснением.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
