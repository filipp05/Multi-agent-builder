# 24: Приёмка и защита всей команды

**Что сделать:** Команда демонстрирует проверенный релиз в отведённое время, каждый участник объясняет свою часть и общую архитектуру.

**Зависит от задач:** 20: Сравнение одного агента и мультиагентной системы на отложенных сценариях; 23: Работающий сервис по ссылке.

**Статус:** черновик; после согласования — метка `ready-for-agent`.

**Ответственный:** D. **Сложность:** 3 баллов. **Этап:** полный учебный MVP.

## Критерии приёмки

- [ ] На развёрнутом сервисе проверены новый запрос к модели, исправление и понятная ошибка. Критических регрессий нет.
- [ ] Матрица требований предварительной и финальной защит заполнена доказательствами. Невыполненные пункты обозначены явно.
- [ ] Каждый показывает минимум один слайд. Сценарии предварительной защиты на 10 минут и финальной на 12 минут отрепетированы с распределёнными ролями.
- [ ] A подтверждает ссылки, время и дедлайн; C проверяет чистоту репозитория; B проверяет понятность. D собирает общий итог, а не выполняет работу остальных.

## Граница задачи

Реализовать один описанный пользовательский путь: контракт данных → прикладной сервис и API → минимальный интерфейс → проверка результата. Не добавлять функции соседних задач. В задачах 01–07 допустимы отдельные тестовые примеры; в задаче 08 те же контракты должны работать в общем потоке через прораба.

## Передача и проверка

Приложить пример входа и выхода, результаты приёмочных проверок, ограничения и журнал настоящего вызова модели, если он предусмотрен задачей. Проверка по кольцу: A → B → C → D → A; стрелка означает «проверяет работу». C и D дополнительно независимо сверяют численные эталоны. Если задача не помещается в одну рабочую сессию, до реализации разделить её по пользовательскому поведению, сохранив зависимости.
