# Ремонт под контролем

Учебный помощник планирования ремонта: пожелания → подтверждённый бриф → две концепции → выбор → работы → закупки и смета → календарь → проверка.

**Работает:** полный локальный сценарий через Codex, сохранение проектов, уточнения, выбор концепции, расчёты и аудит. Реальный прогон 23 октября 2026 создал восемь документов за 96 секунд; контролёр оставил замечания к полноте каталога и технологии. Это один сценарий, не оценка качества всех запросов. Серверный адаптер AWS Bedrock готов, но живой запуск нашего аккаунта заблокирован нулевой токенной квотой.

**Границы:** одна сухая комната, подготовленное основание, покраска стен и ламинат. Каталог, цены и нормы учебные. Изображений, 3D и автоматического исправления плана после аудита пока нет. Непроверенные условия явно отмечаются; результат не заменяет профессиональную смету.

## Быстро попробовать через Codex

Нужны Python 3.12, установленный Codex CLI и личная авторизация с доступом к модели. Из корня репозитория:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-app.txt
codex login
.venv/bin/python scripts/run_mvp.py --provider codex --model gpt-6-astra
```

Открыть http://127.0.0.1:8000. Codex вызывает удалённую модель через подписку; интернет необходим. Секреты остаются на компьютере. API-ключ OpenAI не нужен. Модель можно заменить флагом `--model` на доступную вашему аккаунту.

Пример: «Покрасить стены и уложить ламинат в комнате 5×4 м, высота 2,7 м, проёмы 3 м². Основание подготовлено. Москва, бюджет 200 000 ₽, с 1 ноября до 1 декабря 2026. Одна бригада, пн–пт, 8 часов с 9 утра».

Подтвердите требования, перейдите к концепциям, выберите вариант. В плане доступны работы, закупки, смета с резервом, график и замечания аудитора. `constraints_unresolved` означает, что остались непроверенные условия; это не полностью одобренный план.

## Запуск Docker с AWS Bedrock

Нужны Docker, ключ Bedrock, доступ к указанной модели и ненулевая квота в `us-east-2`. Кредиты AWS сами по себе не открывают квоту. Codex CLI и личная авторизация **не включены** в этот Docker-образ.

```bash
cp .env.example .env
# В редакторе замените только placeholder ключа на свой. Не публикуйте .env.
chmod 600 .env

docker build --target runtime -t renovation-mvp .
docker volume create renovation-data
docker run --rm -v renovation-data:/data --user root --entrypoint chown renovation-mvp 10001:10001 /data
docker run -d --name renovation-mvp --env-file .env \
  -p 127.0.0.1:8000:8000 -v renovation-data:/data renovation-mvp
curl --fail http://127.0.0.1:8000/health
```

Если порт 8000 занят локальным демо, используйте `-p 127.0.0.1:8001:8000` и адрес с портом 8001. `/health` проверяет процесс, а не доступ модели. При нулевой квоте интерфейс откроется, но генерация вернёт ошибку. Полная проверка — получить результат нового проекта с настоящей моделью.

Остановка: `docker stop renovation-mvp`; удаление контейнера: `docker rm renovation-mvp`. Повторите `docker run` после обновления `.env`: перезапуск старого контейнера не перечитывает файл. Данные в volume сохраняются; не удаляйте его для перезапуска.

Конфигурация — [.env.example](.env.example). Launcher не загружает `.env` автоматически: локальному Bedrock-процессу передайте переменные через окружение. HTTPS и закрытый командный доступ на VPS — [инструкция деплоя](docs/deployment.md).

## Где используется LLM

| Режим | Провайдер и модель | Статус |
|---|---|---|
| Локальное демо | Codex CLI через ChatGPT, `gpt-6-astra` | Проверен живой полный проход |
| Docker / сервер | AWS Bedrock Converse, `amazon.nova-lite-v1:0`, Ohio | Адаптер и ошибки проверены; живой ответ блокируется квотой аккаунта |

LLM извлекает пожелания, помогает уточнить бриф, формулирует концепции, выбирает из разрешённых товаров, объясняет смету/календарь и ищет смысловые противоречия. **Python** считает геометрию, упаковки, деньги и даты, проверяет схемы и инварианты. После брифа — пять вызовов модели; уточнения и повторы могут увеличить число. Все роли используют один настроенный провайдер. Переключение: перезапустить launcher с `--provider codex` или `--provider bedrock`; для Bedrock ключ передаётся приватно через окружение.

## Структура

```text
app/
  main.py              # общий веб-интерфейс и API
  pipeline.py          # последовательность этапов, ревизии, сохранение
  brief/               # пожелания, уточнения и подтверждение (A)
  design/              # концепции и технология (B)
  procurement/         # закупки и смета (C)
  planning/            # график и независимый аудит (D)
  providers/           # адаптер Bedrock; Codex пока в brief/model.py
  static/              # интерфейс полного плана
contracts/             # JSON-схемы, передача данных, примеры
tests/                # проверки по тем же функциональным модулям
evals/brief/           # качество первого этапа, данные и запуск
scripts/              # запуск MVP и диагностические утилиты
docs/                 # актуальная архитектура и инструкции
  modules/             # подробности каждого модуля
  archive/             # исторические планы, не текущие обязательства
team/                 # участники, инструкции и навыки
```

Схемы и сохранённые данные не переименованы. Старые вспомогательные HTTP-адреса `/oleg/` и `/karina/` сохранены для совместимости; основной сценарий — `/` и `/plan`. После переименования пакетов перезапустите разработческий процесс. [Карта старых и новых путей](docs/architecture.md#переезд-папок).

## Проверки и разработка

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python -m pytest -q
```

Тесты не требуют ключей и подменяют модель. Отдельный Docker-набор:

```bash
docker build --target test -t renovation-mvp-test .
docker run --rm renovation-mvp-test
```

Программные тесты не доказывают качество живой модели. Историческая метрика 88/90 относится только к известному набору первого этапа; сквозную оценку ещё предстоит расширить. Детали — [проверки и ограничения](docs/validation.md).

Изменения — через PR и зелёный CI. Контракты меняются согласованно. Личные данные, ключи, рабочие базы и сырые переписки не коммитятся; `.scratch/` полностью исключена из Git.
