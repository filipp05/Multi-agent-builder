# Задание помощнику: Карина

Скопируй текст ниже в помощника, открыв общий репозиторий. Начинай в отдельной ветке `work/karina` от актуальной `main`.

---

Я отвечаю за направление «график и проверка». Прочитай `team/karina/README.md`, `contracts/README.md`, `contracts/RULES.md` и `.scratch/shared-contracts/issues/03-karina.md`. Полная постановка — `.scratch/renovation-mvp/SPEC.md`.

Реализуй мой пользовательский путь целиком, включая минимальный интерфейс и проверки. Мои выходные документы: `schedule, audit`. Используй общий интерфейс обработчика `handler(context) -> (result, artifact_or_none)` из `contracts/handoff.py`. Общие идентификаторы выдаёт координатор. Сохраняй существующие имена полей, единицы и статусы.

Чужие этапы на время разработки замени явно обозначенными примерами из `contracts/examples/completed.json`. Не выдавай примеры за результат модели. Не копируй чужую реализацию в свою папку. Код приложения размещай в общем пакете `app`, свою область — в `app/karina`; общий запуск, API и модельный адаптер ведёт Филипп. Пакет приложения ещё предстоит создать. Личные папки `team` предназначены для инструкций.

Сначала запусти `python -m pytest -q` и `python -m contracts.handoff contracts/examples/completed.json`. Затем реализуй мою часть, добавь проверку реального поведения, повтори проверки. При необходимости изменить общий договор сначала опиши несовместимость и согласуй изменение с затронутым участником; не меняй поле молча.

Перед передачей покажи: что работает, как запустить, пример входа и выхода, результаты проверок, ограничения. Секреты храни только в локальном окружении. Если задача требует модель, доступ к ней должен настраиваться извне; не выдумывай модель или ключ и не заявляй о выполненном вызове без проверки.
